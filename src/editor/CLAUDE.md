# src/editor/CLAUDE.md

Helpers that touch the `vscode` API on behalf of `commands/` and `snippets/`. This is the **only** home for clipboard reads and notification toasts outside `commands/` and `extension.ts` (snippet building also lives in `snippets/` and `drop/`).

## Files

- `file-path-info.ts` — single source of truth for `{ relativePath, sourceFilePath, destinationFilePath, sourceFileExt, destinationFileExt }`; also home of the pure clipboard-line helpers `parseClipboardPaths` / `filterCopyablePaths`.
- `placement.ts` — placement-rule helpers, consumed two distinct ways. **Low-level helpers** (`isInlineSnippet`, `shouldRepositionCursor`, `isCommentLine`, `getLineIndentation`, `detectBlockIndentation`, `isMarkdownDestination`, `isFrameworkStyleDestination`, `adjustForCommentBlock`, `findAstroFrontmatterBounds`, `findSfcScriptBounds`, `findEnclosingStyleBounds`, `findBottomLineInRange`, `isImportLine`) are imported by `insert-snippet.ts`, which composes them with its own editor-side insertion logic. **High-level `computeImportPlacement`** (plus the `ComputedPlacement` interface) is used only by `drop/provider.ts`, which delegates the whole placement decision to it. **The gesture-level detector `isStyleBlockContext`** (pure, no editor read) decides whether a paste/drop into a framework SFC takes the `<style>`-block stylesheet dialect — it is consumed by the copy/paste commands and `drop/provider.ts` to compute the `insideStyleBlock` flag they thread into snippet-building and placement. See the placement-rules section below.
- `insert-snippet.ts` — snippet-insertion orchestrator. Delegates to `placement.ts` for placement decisions, then calls `editor.insertSnippet` at the computed position.
- `notification.ts` — single switch on `NotificationType` plus a `clearNotifications()` helper.

## `file-path-info.ts:getFilePathInfo()`

- Reads source from clipboard, destination from `vscode.window.activeTextEditor.document.uri.fsPath`.
- **Caller is responsible for the active-editor null check** — this function dereferences `editor.document.uri.fsPath` unconditionally and will raise a `TypeError` otherwise. Every command that starts the calling chain (`commands/paste-import.ts`, `commands/paste-import-with-style.ts`, `commands/set-default-import-style.ts`) does this check.
- **Async variant re-reads the clipboard on every call.** `getFilePathInfoFromPaths` (sync) is called by `drop/provider.ts` with explicit paths — no clipboard read.
- Called from: `commands/{paste-import,paste-import-with-style,set-default-import-style}.ts` (async variant `getFilePathInfo`, single-path flows) and `drop/provider.ts` + the multi-path command flows (sync variant `getFilePathInfoFromPaths`, explicit paths). Language modules, `dispatch.ts`, `variants.ts`, and `insert-snippet.ts` all receive `FilePathInfo` as a parameter — they do not call this function themselves.
- **Clipboard-line helpers (pure, no `vscode` read).** `parseClipboardPaths(raw)` splits raw clipboard text into trimmed, non-empty lines — VS Code's built-in `copyFilePath` newline-joins an Explorer multi-selection, so each line is one copied file. `filterCopyablePaths(paths)` keeps the **absolute** members (copy is destination-agnostic, so it no longer requires an extension — an extensionless file is a valid Markdown-link source; the paste-time gate rejects it into a non-`.md` destination). Consumers: `commands/copy-file-path.ts` (parse + filter), and the multi-path forks in `commands/paste-import.ts`, `commands/paste-import-with-style.ts`, `commands/set-default-import-style.ts` (parse).

## `placement.ts` and `insert-snippet.ts` — placement rules

`insertImportSnippet(snippet, info)` receives a pre-computed `FilePathInfo` from the calling command — it does not call `getFilePathInfo()` itself. The low-level placement-rule helpers live in `placement.ts`; `insert-snippet.ts` orchestrates the insertion by calling those helpers and then `editor.insertSnippet`.

**Two placement strategies share these precedence rules.** The order below applies to the **command flow** via `insertImportSnippet`, which reads from the active editor and ends in `editor.insertSnippet`. The **drop flow** (`drop/provider.ts`) instead calls `computeImportPlacement(documentText, destinationFileExt, sourceFileExt, dropLine, dropColumn, insideStyleBlock?)` — a pure function in `placement.ts` that applies the *same* precedence but returns a `ComputedPlacement` (`{ line, column, indentation, isInline, wrapperPrefix?, wrapperSuffix? }`) for a `WorkspaceEdit`, never touching the editor. Both entry points take the trailing `insideStyleBlock` flag (default `false`) — the caller computes it once per gesture via `isStyleBlockContext` and passes it through. The two implementations duplicate the precedence logic across the command flow (`insertImportSnippet` routing to `insertSnippetAtTop`, `insertSnippetAtBottom`, `insertSnippetAtCursor`, `insertSnippetAtStyleBlock`, `insertSnippetAtAstroFrontmatter`, `insertSnippetAtSfcScript`) and the drop flow (`computeImportPlacement` routing to `computeStyleBlockPlacement`, `computeAstroPlacement`, `computeSfcPlacement`), plus inline-snippet handling in both, and must be kept in sync when placement logic changes. See `src/test/editor/placement-parity.test.ts` — a comprehensive parity test that validates the two flows produce identical line placement across the placement settings and all destination block types (SFC `<style>` block, Astro frontmatter, SFC script, and flat files), plus identical columns wherever the gestures agree. The forced-cursor destinations are the deliberate exception: those scenarios are flagged `dropForcesColumnZero` and assert each side separately (paste keeps the caret column, drop forces 0).

Order of precedence:

1. **Inline snippet** (`isInlineSnippet` returns true) — non-stylesheet source into a stylesheet destination (e.g. image → `.css`/`.scss`). Inserts the `url('...')` snippet at the exact cursor position (line *and* column from `editor.selection.anchor`) with **no trailing newline**. Bypasses `determineInsertionColumn` and the `\n` append entirely, since `url()` is an inline CSS value, not a standalone statement.
2. **Forced cursor** (`shouldRepositionCursor` returns true) — destination is `.html`, `.md`, or `.tex`. Appends `\n` and inserts at the cursor line via `insertSnippetAtCursor`. The insertion **column is gesture-split** here: the command flow keeps the caret column (via `determineInsertionColumn`, which returns the cursor column for these non-script/non-stylesheet destinations), while the drop flow forces column 0 so a dropped import takes its own line above the drop point. A caret column is typing intent — an inline `<img>` or link belongs exactly where the user is typing — whereas a drop column is only where the mouse button came up. For `.tex` this keeps a figure / `\input` in the document **body** — line 0 is the LaTeX preamble; the multi-line figure shape lands at the cursor line and VS Code re-indents its interior lines to the insertion column. Note: `.mdx` is *not* forced-cursor — `shouldRepositionCursor` checks `.html`/`.md`/`.tex`, so `.mdx` follows the user's Top/Bottom/Cursor setting. It is still treated as Markdown for comment-line handling (`isMarkdownDestination` returns true for `.md` *and* `.mdx`), so a leading `*` counts as content, not a comment.
3. **SFC `<style>` block** (destination is `.vue`/`.svelte`/`.astro` **and** the gesture's `insideStyleBlock` flag is set — a stylesheet source pasted/dropped strictly inside a `<style…>`…`</style>` block) — constrains insertion to that enclosing style block via `insertSnippetAtStyleBlock`. `findEnclosingStyleBounds` locates the block strictly containing the cursor/drop line (a line *on* a tag is outside), and placement mirrors the Astro/SFC blocks: **Top** after the opening tag; **Bottom** after the last `IMPORT_INDICATORS` match in the block (falls back to after the opening tag); **Cursor** at the gesture line. If the block can't be re-located it falls back to Bottom. This branch precedes the Astro/SFC-script branches, so a stylesheet-into-`<style>` gesture takes the style dialect while every other source into the same destination still routes to frontmatter/script placement. See `src/snippets/CLAUDE.md` for how the dialect (`@import`/`@use`) is chosen.
4. **Astro frontmatter** (destination is `.astro`) — reads the user's placement setting and constrains insertion to within the `---` frontmatter fences via `insertSnippetAtAstroFrontmatter`. `findAstroFrontmatterBounds` locates both fences (returns `null` if fewer than two exist). If no frontmatter exists, all three modes converge: wraps the import in a new `---` block at line 0. Within an existing frontmatter block: **Top** inserts after the opening `---`; **Bottom** scans the frontmatter region for import lines via `isImportLine` and inserts after the last match (falls back to after the opening `---`); **Cursor** inserts at the cursor line if it's inside the fences, otherwise falls back to Bottom.
5. **SFC script block** (destination is `.vue` or `.svelte`) — constrains insertion to within a `<script...>` / `</script>` pair via `insertSnippetAtSfcScript`. `findSfcScriptBounds` prefers `<script setup` (Vue composition API), then a bare instance `<script` that is not a module script (excludes Svelte's `<script context="module">`), then falls back to the first `<script` block found. Placement logic mirrors Astro: **Top** inserts after the opening tag; **Bottom** scans the block for import lines via `isImportLine` (falls back to after the opening tag); **Cursor** inserts at the cursor line if inside the block, otherwise falls back to Bottom. If no script block exists, wraps the import in a new `<script>` / `</script>` pair at line 0.
6. **User setting** `auto-import.preferences.importStatementPlacement` — `'Top'` / `'Bottom'` / `'Cursor'` matched **literally** as strings. Adding a new placement requires the `enum` in `package.json` plus `switch` statements kept in sync across both files: in `insert-snippet.ts`, `insertImportSnippet`, `insertSnippetAtStyleBlock`, `insertSnippetAtAstroFrontmatter`, and `insertSnippetAtSfcScript`; in `placement.ts`, `computeImportPlacement`, `computeStyleBlockPlacement`, `computeAstroPlacement`, and `computeSfcPlacement`. (Each file has one general switch plus the style-block, Astro-frontmatter, and SFC-script variants.) Any value other than these three strings falls through to the default case and receives Bottom placement.

### "Bottom" insertion

Walks `document.getText().split('\n')` and inserts after the last line that satisfies `isImportLine` — the predicate that tests each line against the `IMPORT_INDICATORS` markers:

```
'import ', 'require(',
"@import '", '@import "', '@import url(', "@use '", '@use "',
"@forward '", '@forward "'
```

`isImportLine` matches the *line-leading* markers (`import `, the `@import` family, `@use`, `@forward`) only when they start the trimmed line, so an `import ` substring inside a string literal (`const msg = "you should import this"`) is **not** counted. `require(` is a call expression rather than a line-leading keyword, so it is matched anywhere on the line — a `require(` substring inside a string literal stays a residual false positive (far rarer, and not removable without full string-literal parsing). Comment lines (starting with `//`, `/*`, or `*` after whitespace) are additionally skipped via `isCommentLine`. Falls through to line 0 when nothing matches. **New import-syntax markers must be added to `IMPORT_INDICATORS`** or "Bottom" placement will silently land at line 0 instead of after the existing imports.

### Insertion column

`determineInsertionColumn(editor)` in `insert-snippet.ts` returns `0` for destinations whose extension is in `constants/extensions.ts:SCRIPT_FILE_EXTENSIONS` or `STYLESHEET_FILE_EXTENSIONS`; otherwise the cursor's column (important for HTML/Markdown where the user is typing inline). It is **command-flow-only**: `computeImportPlacement` hardcodes column 0 on every non-inline branch, forced-cursor included, so a dropped import always lands on its own line. This is the one place the two flows deliberately diverge rather than mirror each other — see the gesture-split note in precedence rule 2. The inline `url()` branch is unaffected in both flows: it keeps the exact cursor/drop column, because a `url()` is a CSS value rather than a standalone statement.

## `notification.ts:showNotification(type, payload?)` and `clearNotifications()`

### `showNotification(type, payload?)`

- Overloaded function dispatching on `NotificationType` (string-literal union from `types/notification.ts`).
- The variants split into payload-less ones and ones that interpolate values into the message:
  - `'not-supported'` takes `{ sourceExt, destinationExt }` — emits `Auto Import: Cannot import .X into .Y files.`
  - `'no-extension'` takes `{ basename }` — emits `Auto Import: <basename> has no file extension — only Markdown links support extensionless files.` Fires at paste/drop time for an extensionless source into a non-`.md` destination (into `.md` it imports as a link); copy no longer raises it.
  - `'source-not-found'` takes `{ basename }` — emits `Auto Import: Source file no longer exists: <basename>.`
  - `'copy-success'` takes `{ basenames }` (one entry per copied file) — emits `Auto Import: Copied path — <basename>` for a single entry, and `Auto Import: Copied <N> paths — <basenames>` for more (the list shows the leading three basenames and elides the rest as `+K more` via the module-private `formatBasenameList`) (info toast, not warning)
  - `'no-configurable-style'` takes `{ sourceExt, destinationExt }` — emits `Auto Import: .X → .Y imports use a fixed style.`
  - `'default-style-saved'` takes `{ description }` — emits `Auto Import: Default style saved — <description>` (info toast, not warning)
  - `'placement-saved'` takes `{ placement }` — emits `Auto Import: Import placement saved — <placement>` (info toast, not warning)
  - `'preserve-script-extension-toggled'` takes `{ enabled }` — emits `Auto Import: Preserve script file extension — On`/`Off` (info toast, not warning)
  - `'styles-reset'` takes `{ count }` — emits `Auto Import: Reset 1 import style to defaults` (when `count === 1`) / `Auto Import: Reset <count> import styles to defaults` (info toast, carries an **Undo** button, returns `Thenable<string | undefined>`)
- TypeScript overload resolution enforces the right payload (or no payload) at every call site. The implementation signature uses a wide payload type and `!` non-null assertions because the overloads are the type-safety boundary.
- Warning variants render via `showWarningMessage`; the info variants (`'copy-success'`, `'default-style-saved'`, `'placement-saved'`, `'preserve-script-extension-toggled'`, `'styles-reset'`, `'no-styles-to-reset'`, `'styles-restored'`) render via `showInformationMessage`. The level is hardcoded per-variant inside the `switch`.
- These variants surface action buttons:
  - `'not-supported'` adds **View Supported Files** — click handler is self-contained (`vscode.env.openExternal` to the README's `#supported-languages` anchor). The `showWarningMessage(...).then(...)` chain is prefixed with the `void` operator to discard its promise on the spot, so the overload returns `void`.
  - `'copy-success'` adds **Paste with Style** (style-picker variant) and **Paste Now** (default paste-import), in that render order (leftmost first). The overload returns `Thenable<string | undefined>` so `commands/copy-file-path.ts` can dispatch on the chosen action — keeps `editor/` from reaching into `commands/`.
  - `'styles-reset'` adds **Undo** — the overload returns `Thenable<string | undefined>` so `commands/reset-import-styles.ts` can restore the captured prior values via `restoreImportStyles` when clicked. Same byte-exact button-label contract as `'copy-success'`, paired with `reset-import-styles.ts`.
- Producers: `commands/paste-import.ts` raises (`'same-file-path'`, `'not-supported'`, `'no-active-editor'`, `'no-extension'`, `'empty-clipboard'`, `'source-not-found'`); `commands/paste-import-with-style.ts` raises the same set plus its branch on `variants.length`; `commands/copy-file-path.ts` raises (`'no-file-to-copy'`, `'copy-success'`) — **no longer `'no-extension'`, since an extensionless copy now succeeds**; `commands/set-default-import-style.ts` raises the same rejection set plus `'no-configurable-style'` and `'default-style-saved'`; `drop/provider.ts` raises (`'same-file-path'`, `'not-supported'`, `'no-extension'`); the settings commands raise their own info toasts — `'placement-saved'` from `commands/set-import-placement.ts`, `'preserve-script-extension-toggled'` from `commands/toggle-preserve-script-extension.ts`, and `'no-styles-to-reset'` / `'styles-reset'` / `'styles-restored'` from `commands/reset-import-styles.ts`.
- All messages share the `Auto Import:` prefix — matches the command titles in `package.json`.

### `clearNotifications()`

- Wraps `vscode.commands.executeCommand('notifications.clearAll')` so commands don't reach into the VS Code command palette directly for notification-system side effects.
- Fire-and-forget — the underlying `executeCommand` returns a Thenable that's deliberately not awaited.
- Producers: every copy/paste command (`commands/paste-import.ts`, `commands/copy-file-path.ts`, `commands/paste-import-with-style.ts`, `commands/set-default-import-style.ts`) calls this at the top of its execution to dismiss any lingering toasts before a fresh one fires. `copy-paste.ts` inherits via the two it composes. The settings commands (`set-import-placement.ts`, `toggle-preserve-script-extension.ts`, `reset-import-styles.ts`) do **not** call it — they emit info toasts and never run the gating preamble.
- This is the **only** allowed entry point for `notifications.clearAll` outside of `notification.ts`. Commands must not inline the `executeCommand('notifications.clearAll')` call.
